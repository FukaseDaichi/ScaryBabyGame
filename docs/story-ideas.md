# ストーリー案 — 這う子の十夜

`ScaryBabyGame` に物語性を与えるための案を10本まとめる。
現状は「真っ暗な屋敷を赤ちゃんがハイハイで進み、幽霊とガーゴイルの視線を避けてゴールに着く」ところまで動いている。
足りないのは **なぜ這うのか** と **見つかると何が起きるのか** の2つだけ。
以下はすべて、いまあるアセットとスクリプトの上に乗ることを条件に組んである。

## いま手元にある素材

- ほぼ真っ黒な環境光と、屋敷全体を一瞬照らす雷（`LightningFlash.cs`）
- 幽霊8体・ガーゴイル3体の視線判定（`Observer.cs` のレイキャスト）
- 赤ちゃんが持つ小さな橙の明かり（`Baby_Glow`）
- 幽霊の接近ループ音（距離減衰カーブ調整済み）
- 骨格だけ書かれた鍵と扉（`Key.cs` / `Door.cs`）
  - **注意**: 両者は `StealthGame` 名前空間にあり `StealthGame.PlayerMovement`（旧デモ版、`AddKey`/`OwnKey` を持つ）を参照している。
    `Player.prefab` に載っているのはグローバル名前空間の `Scripts/PlayerMovement.cs` なので、
    現状の `GetComponent<PlayerMovement>()` は常に null を返し、鍵も扉も無反応。使うには参照の張り替えが要る。
- 7種類の部屋プレハブと Level A / B / C（`Main.unity` には Level A と Level C を配置）
- 勝ち・負けの2画面（`GameEnding.cs`、負けは `Main` シーンの再読み込み）

## 一. なぜ這うのか — プレイヤーに目的を与える

### 1. おかあさんのところへ

> 雷の夜、ベビーベッドから落ちた赤ちゃんが、玄関で待つ母の声だけを頼りに屋敷を這う。

引っ越してきた最初の夜。停電した屋敷で目を覚ますと、赤ちゃんは二階のベビーベッドから床に落ちていた。
遠くで母が名前を呼んでいる。だがこの屋敷には、かつてここで我が子を亡くした女がいて、
赤ちゃんを見つけると「やっと帰ってきた」と言って抱き上げる。

- **「見つかる」とは**: 殺されるのではなく、優しく抱き上げられて連れて行かれる。母の呼び声が遠ざかっていく。
- **いまある仕組み**: `Baby_Glow` は母がくれたお守りの灯りになる。幽霊の接近ループ音を子守唄のハミングに差し替えるだけで、いまの距離減衰演出がそのまま恐怖になる。`Room_Finish` は玄関。
- **トーン**: 王道・情緒／説明が一切いらない　**実装コスト**: 小

### 2. ミルクの匂い

> 目的は脱出ではなく一杯のミルク。泣けば見つかる。泣かなければ、もう動けない。

時間が経つほど空腹が募り、限界を超えると赤ちゃんは自分の意思と関係なく泣き出して、屋敷中の霊に位置を知らせてしまう。
泣くのを止める手段はおしゃぶりを咥えること。ただし咥えている間は明かりが消え、自分もまた何も見えない。
空腹という生理が、そのままステルスの時限装置になる。

- **「見つかる」とは**: 泣き声を聞きつけた「乳母」が来る。声を我慢しきれなかったこと自体が敗因になる。
- **いまある仕組み**: ゴールが `Room_Kitchen` になり、レベル終端の作り直しが不要。`Key.cs` / `Door.cs` をミルク瓶と食器棚の扉に流用できる（案5と同じ、参照先の張り替えが要る）。
- **トーン**: システム主導／緊張が持続する　**実装コスト**: 中

### 3. 朝までの留守番

> 両親が一晩だけ祖母の家に預けた。祖母は三年前に死んでいる。

目的は「脱出」ではなく「朝まで見つからずにいること」。屋敷の霊たちは悪意のない、世話焼きの乳母である。
ただし彼女たちに寝かしつけられた子は、二度と外に出てこない。
雷が七度鳴れば夜明け——時間の経過そのものが勝利条件になる。

- **「見つかる」とは**: 優しく抱かれ、寝かしつけられて終わる。悲鳴のない、いちばん静かなバッドエンド。
- **いまある仕組み**: `LightningFlash.cs` の発生回数がそのままタイマーになる（すでにコルーチンでループしているので数えるだけ）。ゴール地点が不要になり、レベル設計の自由度が上がる。
- **トーン**: 時間との勝負／ゴール地点が要らない　**実装コスト**: 小

## 二. 何が起きているのか — 正体を仕掛ける

### 4. 取り替え子

> この赤ちゃんは、屋敷が「本物」と取り替えるために攫ってきた子だ。

巡回する霊たちは、人間の赤ちゃんの匂いを探している。夜明けまでに外へ出られなければ、この子は屋敷の子になる。
捕まってやり直すたび、赤ちゃんの見た目がわずかに変わっていく——肌の色、目、そして手に持つ明かりが橙から青白へ。
プレイヤーが何度も失敗したという事実そのものが、物語として蓄積される。

- **「見つかる」とは**: 一段階、人間でなくなる。何度目かの失敗で、もう追われなくなる（＝仲間として扱われる）。
- **いまある仕組み**: `GameEnding.cs` の `LoadScene("Main")` に失敗回数を持たせるだけで成立する。表現はマテリアルと `Baby_Glow` の色の差し替えで足りる。
- **トーン**: メタ・ループ／リスタートに意味が乗る　**実装コスト**: 中

### 5. 兄が置いていったもの

> 部屋のすみに落ちたクレヨンの絵を拾い集めると、この屋敷にいた「もう一人の子」の話が分かる。

各部屋に、兄が残した絵と落書きが落ちている。集めるほどに、幽霊のうち一体だけが赤ちゃんを追ってこないことに気づく。
全部集めると、最後の扉の前でその一体が扉を開けてくれる。集めなくてもクリアはできるが、その場合は自力でこじ開けることになる。

- **「見つかる」とは**: 兄の絵と同じ構図で、赤ちゃんが屋敷の家族写真に描き加えられる。
- **いまある仕組み**: 収集と施錠扉の骨格は `Key.cs` / `Door.cs` に既にある。ただし両者は旧デモ版の `StealthGame.PlayerMovement` を見ているため、現行の `Scripts/PlayerMovement.cs` に所持リストを持たせて参照を張り替えないと無反応のまま（差分は10行程度）。部屋が7種類あるので、絵も7枚で割り切れる。
- **トーン**: 収集 × 物語／周回の動機になる　**実装コスト**: 中

### 6. 夢の中の我が家

> 幽霊屋敷ではない。ここは自分の家で、化け物は全部、家具だった。

プレイ中は徹底してホラーとして見せる。だが最後の扉を抜けると朝で、カメラが引くと、屋敷がごく普通のリビングだったと分かる。
幽霊はカーテン、ガーゴイルは柱時計、赤い視線はテレビの待機ランプ。
赤ちゃんの主観では世界がそう見えていた、という叙述の反転。

- **「見つかる」とは**: 泣き出して母に抱き上げられる。負けではあるが、実はいちばん安全な結末——恐怖の意味が裏返る。
- **いまある仕組み**: 敵モデルは一切変えない。エンディングで `RenderSettings.ambientLight` を上げて同じ部屋を明るく見せるカットを足すだけで、種明かしの絵が作れる。
- **トーン**: どんでん返し／怖さの理由を説明できる　**実装コスト**: 中

### 7. 家族写真

> 部屋を進むごとに、廊下の写真に写る人数が一人ずつ増えている。

セリフもテキストも一切出さず、壁の写真だけで語る。序盤の写真には夫婦だけ。中ほどでは子どもが一人。
終盤の一枚には、赤ちゃんが写っている。プレイヤーが「自分はもう連れて行かれた後だ」と気づいた瞬間が、この案のピーク。
ゴールに着いても外は暗いままで、玄関の写真の中で母が笑っている。

- **「見つかる」とは**: その場では何も起きない。次のやり直しで、写真がもう一枚だけ増えている。
- **いまある仕組み**: `Room_Corridor` の壁テクスチャを差し替えるだけで語り切れる。スクリプトはほぼ不要で、他の案と重ねて使える。
- **トーン**: 環境ナラティブ／他案と併用できる　**実装コスト**: 小

## 三. 仕組みが物語になる — ルールそのものを物語で説明する

### 8. 雷の子

> 雷が光る一瞬だけ、この子は誰の目にも映らない。

赤ちゃんは雷の夜に生まれた。雷鳴が轟く数秒のあいだ、幽霊たちは赤ちゃんを見失う——完全な安全時間。
だが同時にその一瞬は、屋敷の間取りと全幽霊の位置が見える唯一の機会でもある。
雷が鳴るたび、プレイヤーは「見る」か「走る」かを選ばされる。

- **「見つかる」とは**: 雷が止み、屋敷が赤ちゃんを「ただの子ども」として認識する。以後、加護は戻らない。
- **いまある仕組み**: すでにある `LightningFlash.cs` がゲームの中核ルールに昇格する。`Observer.cs` に「閃光中は判定しない」フラグを1つ足すだけで成立し、既存の演出が全部意味を持ち始める。
- **トーン**: システム＝物語／費用対効果が最も高い　**実装コスト**: 小

### 9. ゆりかごの歌

> 握りしめたオルゴールが、唯一の明かりであり、唯一の音でもある。

オルゴールを回せば周囲が照らされる。だが音が鳴っているあいだ、幽霊たちはその方向へ寄ってくる。
止めれば安全だが、真っ暗で何も見えず、家具にぶつかった物音でまた気づかれる。
「見えること」と「見つからないこと」が、完全に両立しない。

- **「見つかる」とは**: 曲が終わる。そして代わりに、暗闇のどこかで誰かが同じ曲を歌い出す。
- **いまある仕組み**: `Baby_Glow` のオン／オフと `AudioSource` を1つのキーに束ねるだけ。幽霊側の距離減衰カーブは調整済みなので、寄ってくる演出にそのまま使える。
- **トーン**: ジレンマ設計／操作が一つ増えるだけ　**実装コスト**: 中

### 10. 七つの夜

> 一晩を生き延びるたび、赤ちゃんは少しだけ大きくなる。

章立ての構成。第一夜はハイハイ——視点が低く、遅く、机の下を通れる。中盤はつかまり立ち——視線が上がって見つかりやすくなる代わりに、扉のノブに手が届く。
最終夜は歩ける——速いが、もうどこにも隠れられない。成長がそのまま難易度曲線であり、物語の進行でもある。屋敷は、この子が大きくなるのを待っている。

- **「見つかる」とは**: その夜がやり直しになる。ただし成長は巻き戻らない。失敗するほど、隠れにくい体になっていく。
- **いまある仕組み**: `Level A / B / C` のプレハブが三つの夜になる。`Observer.cs` の視線が届くかどうかは既にプレイヤーの当たり判定の高さで決まっているので、「成長」は数値変更だけで難易度に直結する。
- **トーン**: 長期拡張／最も野心的　**実装コスト**: 大

## どれから手をつけるか

10案は排他ではない。土台を1本決めて、上に薄い層を重ねるのが早い。

| | 案 | 理由 |
|---|---|---|
| 最短で効く | **8 雷の子** | `Observer.cs` にフラグを1つ足すだけで、すでに作り込んだ雷の演出が「ルール」に変わる。物語とゲーム性が同時に手に入る唯一の案。 |
| 物語の軸 | **1 おかあさんのところへ** | 8 と矛盾しない——「雷の夜に生まれた子が、母のもとへ帰る」で一本にまとまる。まずこの2つを重ねるのを推す。 |
| 眠った資産 | **5 兄が置いていったもの** | 書かれたまま動いていない `Key.cs` / `Door.cs` を、10行程度の張り替えで起こせる。7部屋 = 7枚の絵で、レベル全体に探索の理由が生まれる。 |
| 重ねやすい | **7 家族写真** | テクスチャの差し替えだけで済むので、どの案の上にも無料で乗る。 |
| 最終形 | **10 七つの夜** | 長く作り続けるなら、これを完成形に置いて、第一夜を 1 + 8 で作るのが自然な道筋になる。 |
